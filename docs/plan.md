# 项目规划

## 目标

建立个人 AI 开发工作台，从 GitHub、飞书和工作台接收任务，经过授权与任务管理后，选择不同的 Agent 执行，并在工作台中审查进度和结果。

## 参考项目

- [Orca](https://github.com/stablyai/orca)：参考桌面工作台、多 Agent、终端、工作区、Git worktree 和代码变更审查。优先评估作为工作台和执行环境的可行性。
- [dsh-superagent-prototype](https://github.com/deepseek-ai/dsh-superagent-prototype)：参考 GitHub、飞书事件接入、授权、任务处理和结果反馈。该项目是面向单仓库的研究原型，现有执行流程依赖 DeepSeek Harness，不假定可以直接切换执行器或直接用于生产。
- [OpenHands](https://github.com/OpenHands/OpenHands)：作为浏览器工作台和 Agent 接入方案的备选参考。

以上是初步方向，具体复用方式须通过源码和许可证审查确认。复用或分发第三方代码时保留相应版权声明和许可证。

## 拟议架构

```text
GitHub / 飞书 / 工作台手动创建
              ↓
      事件接收、去重、授权
              ↓
        任务创建与状态管理
              ↓
    执行器适配：Codex / Claude / DSH …
              ↓
      独立工作区及 Git worktree
              ↓
       执行、测试、审查结果
              ↓
  工作台展示，并按授权规则反馈原来源
```

任务管理与执行器分离。执行器适配器负责启动、获取进度、取消和获取结果；具体能力、权限确认和会话恢复因 Agent 而异，不能假设完全一致。工作台、任务服务和执行环境的最终边界以源码调研为准。

## 第一版范围

1. 项目与执行器配置：选择仓库、工作目录、默认 Agent 和执行权限。
2. GitHub 与飞书接入：接收指定来源的事件，校验发送者和事件，避免重复创建任务。
3. 任务中心：展示任务来源、状态、执行日志、执行器和结果，支持停止和重试。
4. 隔离执行：每个任务使用独立 worktree，限制工作目录、凭据和执行权限。
5. 审查与反馈：展示代码变更和测试结果；根据明确授权规则创建 PR、评论或回复飞书。

## 后续阶段

- 支持更多 Agent，以及按项目或任务设置执行器。
- 多项目管理、任务路由、定时任务和可配置自动化。
- 多 Agent 协作、任务拆分和结果汇总。
- 改进审计、监控、失败恢复和升级维护。

## 待调研与决策

- 对照源码梳理 dsh-superagent 的 GitHub、飞书监听、授权、任务状态和 DSH session 的耦合程度，判断哪些代码可复用。
- 验证 Orca 的扩展接口、远程运行能力，以及从外部任务服务启动、跟踪和停止 Agent 的方式。
- 确定工作台形态、运行环境、项目数量、存储方案和身份认证方式。
- 定义外部事件的授权、去重、重试、审计，以及 Agent 的权限和隔离边界。
- 定义每种 Agent 的安装、认证、交互、恢复、取消和费用限制。
- 确定自动回复、提交和创建 PR 等外部操作的授权规则。
- 明确第三方许可证、依赖版本与上游更新策略。

## 建议实施顺序

1. 对 Orca 与 dsh-superagent 做源码级对比，输出可复用点、限制和最小可行方案。
2. 验证一个手动任务从创建到启动指定 Agent、查看结果、停止和恢复的闭环。
3. 建立任务持久化、独立 worktree、审查和权限控制。
4. 分别接入 GitHub 和飞书，验证授权、去重、重试和来源反馈。
5. 补齐第二种 Agent 适配，验证切换和失败恢复。

规划不等同于已实现功能；具体范围和技术方案在源码调研后确定。
