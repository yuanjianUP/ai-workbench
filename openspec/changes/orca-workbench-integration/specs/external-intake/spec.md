## Purpose

使 GitHub 与飞书事件能够经过来源校验、授权和去重后进入任务中心，并确保向外部执行的反馈操作遵守明确授权规则和可审计的处理流程。

## ADDED Requirements

### Requirement: 验证与授权外部事件
系统 SHALL 校验各来源事件真实性及发送者授权，未通过验证的事件 MUST 不创建任务或触发执行。

#### Scenario: 无效事件
- **WHEN** 事件来源校验失败或发送者未获授权
- **THEN** 系统拒绝事件并记录拒绝原因，不创建任务

### Requirement: 事件去重
系统 SHALL 持久化来源与事件标识并对重复投递去重，包括服务重启后的重复投递。

#### Scenario: 事件重复投递
- **WHEN** 同一来源的同一事件再次到达
- **THEN** 系统不创建第二个任务，也不重复触发已处理操作

### Requirement: 显式执行与反馈授权
系统 SHALL 默认将外部任务置于待处理状态；只有适用的明确授权规则允许时才自动执行或向来源评论、回复和创建 PR。

#### Scenario: 未配置自动规则
- **WHEN** 已授权事件创建任务但没有适用的自动执行或反馈规则
- **THEN** 任务等待用户处理且不产生外部反馈

#### Scenario: 反馈结果不确定
- **WHEN** 外部反馈请求的结果无法确认
- **THEN** 系统记录不确定状态，不盲目重复发送
